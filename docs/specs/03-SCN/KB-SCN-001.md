# 사용자 시나리오

## 0. 범위와 전제

공개된 지식베이스 사이트(GitHub Pages)와 챗봇 백엔드(Render)가 배포되어 있다는 전제에서, 방문자의 열람·질문과 운영자의 갱신·점검을 다룬다. 결제·계정 등 비목표([[KB-PRD-001]] 2장)는 다루지 않는다.

## 1. 페르소나

#### P1 운영자

지식베이스 주인. Obsidian으로 노트를 쓰고 웹으로 공개한다. **겪는 문제**: 작업 PC에 Python이 없고, 챗봇이 왜 그렇게 답했는지 들여다볼 수단이 없었다. **원하는 것**: 노트 갱신이 간단한 절차로 챗봇까지 반영되고, 검색·답변 과정을 눈으로 확인하는 것.

#### P2 방문자

지식베이스에서 정보를 찾으러 온 사람. **겪는 문제**: 노트가 많아지면 어디 있는지 모르고, 검색으로 찾아도 이해가 안 되면 다시 물어볼 데가 없다. **원하는 것**: 자연어로 묻고, 이해될 때까지 이어서 묻는 것.

## 2. 시나리오

#### S1 노트 열람·탐색

**주체**: P2
**상황**: 검색엔진이나 공유 링크로 사이트에 들어왔다.

1. 노트를 읽다가 위키링크를 눌러 연결된 노트로 이동한다
2. 그래프 뷰에서 주변 노트를 훑어본다

**성공 조건**: Obsidian에서 보던 링크·그래프 구조가 웹에서 그대로 동작한다.
**연관 요구사항**: [[KB-PRD-001#R1]]

#### S2 챗봇에 단발 질문

**주체**: P2
**상황**: 원하는 내용이 어느 노트에 있는지 모른다.

1. 페이지의 챗봇 위젯을 열고 질문을 입력한다
2. 백엔드가 하이브리드 검색(키워드+의미)으로 노트 청크를 찾는다
3. 답변과 참조 노트 출처 목록이 표시된다
4. 출처를 눌러 원문 노트로 이동해 확인한다

**변형 — 노트에 없는 질문**: 추측하지 않고 "지식베이스에서 관련 내용을 찾지 못했습니다"라고 답한다.
**변형 — 콜드 스타트**: 서버가 잠들어 있으면 첫 응답이 느릴 수 있다는 안내 문구가 표시된다.

**성공 조건**: 고유명사로 물어도, 뜻으로 풀어 물어도 해당 노트가 출처에 든다.
**연관 요구사항**: [[KB-PRD-001#R2]] [[KB-PRD-001#R3]] [[KB-PRD-001#R4]]

#### S3 이어서 묻기 (멀티턴)

**주체**: P2
**상황**: [[#S2]]의 답변을 받았지만 더 알고 싶다.

1. 같은 대화창에 "그건 왜 그래?"처럼 직전 답변을 가리키는 후속 질문을 입력한다
2. 챗봇이 앞선 질문·답변 맥락 안에서 질문 의도를 해석한다
3. 해석된 의도로 노트를 다시 검색해, 노트 근거로만 답한다
4. 답변과 출처가 다시 표시된다

**변형 — 새 대화**: 방문자가 새 대화를 시작하면 이전 맥락 없이 [[#S2]]처럼 동작한다.
**변형 — 맥락 근거 없음**: 맥락을 반영해 검색해도 근거가 없으면 찾지 못했다고 답한다.

**성공 조건**: 후속 질문이 맥락 없이 답한 것과 다른, 대화에 맞는 답을 받는다.
**연관 요구사항**: [[KB-PRD-001#R7]] [[KB-PRD-001#R3]]

#### S4 노트 갱신과 재색인

**주체**: P1
**상황**: 노트를 여러 개 추가·수정했고 챗봇도 새 내용으로 답하게 하고 싶다.

1. Obsidian에서 노트를 수정한다
2. 사이트 저장소에 push한다 — 사이트는 자동 반영된다
3. Docker로 재색인 스크립트를 실행한다 (로컬 Python 불필요)
4. 백엔드 저장소에 커밋·push하면 재배포되고, 키워드 색인은 서버 시작 시 자동으로 따라온다

**성공 조건**: 새 노트 내용으로 질문하면 챗봇이 답한다.
**연관 요구사항**: [[KB-PRD-001#R6]] [[KB-PRD-001#R1]] [[KB-PRD-001#R4]]

#### S5 검색·답변 품질 점검

**주체**: P1
**상황**: 챗봇이 이상한 답을 했거나, 맞는 노트를 못 찾은 것 같다.

1. LangSmith에서 해당 질문의 trace를 연다
2. 검색이 어떤 청크를 골랐는지, LLM에 어떤 context가 들어갔는지 확인한다
3. 원인을 판단한다 — 검색이 못 찾은 것인지, 찾았는데 청크에 답이 없는 것인지, 프롬프트 문제인지
4. 필요하면 노트 보강·가중치 조정 등 개선을 결정한다

**성공 조건**: "왜 이렇게 답했나"를 추측이 아니라 trace로 확인할 수 있다.
**연관 요구사항**: [[KB-PRD-001#R5]]
