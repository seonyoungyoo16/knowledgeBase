# USECASE (Cockburn)

## 0. 이 문서의 형식

Cockburn 형식을 따른다. 사용자 목표 수준(`UC-A#`)과 하위기능 수준(`UC-S#`)으로 나누고, 각 유스케이스는 12행 표 + 기본 흐름 + 확장으로 쓴다. 범위 표기: **KB** = 지식베이스 시스템 전체(사이트+백엔드), **BE** = 챗봇 백엔드.

## 1. 액터

| 액터 | 설명 |
|---|---|
| 방문자 | 사이트에서 노트를 읽고 챗봇에 질문하는 사람 ([[KB-SCN-001#P2]]) |
| 운영자 | 노트를 쓰고 배포·재색인·품질 점검을 하는 사람 ([[KB-SCN-001#P1]]) |
| OpenAI API | 임베딩·답변 생성을 제공하는 외부 시스템 |
| LangSmith | trace를 저장·조회하게 해 주는 외부 시스템 |

## 2. 사용자 목표 수준 유스케이스

| 사전조건 | 사이트가 배포되어 있다 |
| 최소 보장 | 페이지가 열린다 |
| 성공 보장 | 위키링크·그래프로 연결 노트에 도달한다 |
| 트리거 | 방문자가 사이트에 접속 |

**기본 흐름**
1. 방문자가 노트 페이지를 연다
2. 위키링크를 눌러 연결된 노트로 이동한다
3. 그래프 뷰에서 주변 노트를 확인한다

**확장**
- **2a. 링크 대상 노트가 비공개/미발행**
  - 2a1. 링크가 렌더링되지 않거나 대상 없음 페이지가 표시된다

#### UC-A2 챗봇에 질문한다

| 항목 | 내용 |
|---|---|
| 범위 | KB |
| 수준 | 사용자 목표 |
| 주 액터 | 방문자 |
| 이해관계자와 관심사 | 방문자: 노트에 있는 내용을 정확히 답받기. 운영자: 노트에 없는 내용을 지어내지 않기 |
| 사전조건 | 백엔드가 기동돼 있고 색인이 존재한다 |
| 최소 보장 | 오류 시 오류임이 표시되고 대화는 유지된다 |
| 성공 보장 | 노트 근거 답변과 출처 목록이 표시된다 |
| 트리거 | 방문자가 위젯에 질문을 입력하고 전송 |
| 패키지 | 챗봇 |
| 포함(include) | [[#UC-S1]] [[#UC-S2]] |
| 확장점 | 후속 질문 → [[#UC-A3]] |
| 일반화 | — |

**기본 흐름**
1. 방문자가 위젯을 열고 질문을 입력한다
2. 시스템이 하이브리드 검색을 수행한다 ([[#UC-S1]])
3. 시스템이 검색 결과에 근거해 답변을 생성한다 ([[#UC-S2]])
4. 답변과 출처 목록이 표시된다

**확장**
- **2a. 관련 청크 없음**
  - 2a1. "지식베이스에서 관련 내용을 찾지 못했습니다"를 표시한다
- **1a. 백엔드 콜드 스타트**
  - 1a1. 지연 안내 문구를 표시하고 응답을 기다린다
- **3a. OpenAI 호출 실패**
  - 3a1. 오류 메시지를 표시한다. 재시도는 방문자 몫이다

**연관**: [[KB-PRD-001#R2]] [[KB-PRD-001#R3]] [[KB-PRD-001#R4]] · [[KB-SCN-001#S2]]

#### UC-A3 이어서 묻는다 (멀티턴)

| 항목 | 내용 |
|---|---|
| 범위 | KB |
| 수준 | 사용자 목표 |
| 주 액터 | 방문자 |
| 이해관계자와 관심사 | 방문자: 앞선 답변을 전제로 추가 질문. 운영자: 맥락이 붙어도 근거 원칙 유지 |
| 사전조건 | 같은 대화에서 [[#UC-A2]]가 1회 이상 성공했다 |
| 최소 보장 | 맥락 해석 실패 시에도 단발 질문으로는 답한다 |
| 성공 보장 | 후속 질문이 대화 맥락에 맞게 답변된다 |
| 트리거 | 방문자가 같은 대화창에 후속 질문 입력 |
| 패키지 | 챗봇 |
| 포함(include) | [[#UC-S1]] [[#UC-S2]] |
| 확장점 | — |
| 일반화 | [[#UC-A2]]의 특수화 |

**기본 흐름**
1. 방문자가 "그건 왜 그래?" 같은 후속 질문을 입력한다
2. 위젯이 대화 이력과 함께 질문을 백엔드에 보낸다
3. 시스템이 이력 맥락 안에서 질문 의도를 해석한다
4. 해석된 의도로 하이브리드 검색을 수행한다 ([[#UC-S1]])
5. 노트 근거로만 답변을 생성하고 ([[#UC-S2]]) 출처와 함께 표시한다

**확장**
- **3a. 맥락과 무관한 새 주제 질문**
  - 3a1. 새 질문으로 그대로 검색한다 (기본 흐름 4로)
- **4a. 맥락 반영 검색에도 근거 없음**
  - 4a1. 찾지 못했다고 답한다
- **1a. 방문자가 새 대화 시작**
  - 1a1. 이력 없이 [[#UC-A2]]로 동작한다

**연관**: [[KB-PRD-001#R7]] [[KB-PRD-001#R3]] · [[KB-SCN-001#S3]]

#### UC-A4 노트 갱신을 챗봇에 반영한다

| 항목 | 내용 |
|---|---|
| 범위 | KB |
| 수준 | 사용자 목표 |
| 주 액터 | 운영자 |
| 이해관계자와 관심사 | 운영자: 로컬 Python 없이 간단히 반영. 방문자: 최신 노트로 답변받기 |
| 사전조건 | 노트가 수정됐다. Docker가 동작한다 |
| 최소 보장 | 실패해도 기존 색인·서비스는 유지된다 |
| 성공 보장 | 새 노트 내용으로 챗봇이 답한다 |
| 트리거 | 운영자가 반영을 결정 |
| 패키지 | 운영 |
| 포함(include) | [[#UC-S3]] |
| 확장점 | — |
| 일반화 | — |

**기본 흐름**
1. 운영자가 사이트 저장소에 노트를 push한다 — 사이트가 자동 배포된다
2. 운영자가 재색인을 실행한다 ([[#UC-S3]])
3. 운영자가 백엔드 저장소에 커밋·push한다
4. 백엔드가 재배포되고, 시작 시 키워드 색인이 새 청크로 재구축된다

**확장**
- **4a. 재배포 실패 (빌드·메모리 등)**
  - 4a1. 기존 버전이 계속 서비스된다. 운영자가 배포 로그로 원인을 확인한다

**연관**: [[KB-PRD-001#R6]] [[KB-PRD-001#R4]] · [[KB-SCN-001#S4]]

## 3. 하위기능 수준 유스케이스

#### UC-S1 하이브리드 검색을 수행한다

| 항목 | 내용 |
|---|---|
| 범위 | BE |
| 수준 | 하위기능 |
| 주 액터 | 챗봇 백엔드 |
| 이해관계자와 관심사 | 방문자: 관련 청크가 빠짐없이 뽑히기 |
| 사전조건 | 벡터 색인(Chroma)과 키워드 색인(BM25)이 메모리에 로드돼 있다 |
| 최소 보장 | 한쪽 검색이 비어도 다른 쪽 결과로 진행한다 |
| 성공 보장 | 두 검색 결과가 순위 융합돼 상위 청크가 선정된다 |
| 트리거 | 질문(또는 맥락 반영 질문) 수신 |
| 패키지 | 챗봇 |
| 포함(include) | — |
| 확장점 | — |
| 일반화 | — |

**기본 흐름**
1. 질문을 형태소 단위로 토큰화해 BM25 검색으로 상위 청크를 얻는다
2. 질문을 임베딩(OpenAI)해 벡터 유사도 검색으로 상위 청크를 얻는다
3. 두 순위를 RRF로 융합하고 중복을 제거한다
4. 상위 N개 청크를 출처 정보와 함께 반환한다

**연관**: [[KB-PRD-001#R4]]

#### UC-S2 노트 근거 답변을 생성한다

| 항목 | 내용 |
|---|---|
| 범위 | BE |
| 수준 | 하위기능 |
| 주 액터 | 챗봇 백엔드 |
| 이해관계자와 관심사 | 운영자: 근거 없는 내용을 지어내지 않기 |
| 사전조건 | [[#UC-S1]]의 청크 목록이 있다 (비어 있을 수 있음) |
| 최소 보장 | LLM 실패 시 오류가 호출자에게 전달된다 |
| 성공 보장 | 청크에만 근거한 한국어 답변이 반환된다 |
| 트리거 | 검색 완료 |
| 패키지 | 챗봇 |
| 포함(include) | — |
| 확장점 | — |
| 일반화 | — |

**기본 흐름**
1. 청크들을 출처 표기와 함께 하나의 context로 병합한다
2. 근거 제한 프롬프트와 함께 LLM(OpenAI)에 보낸다
3. 답변 문자열과 출처 목록을 반환한다
4. 추적이 활성화돼 있으면 전 과정이 하나의 trace로 기록된다 ([[KB-PRD-001#R5]])

**확장**
- **1a. 청크가 비어 있음**
  - 1a1. "관련 노트 없음"을 context로 보내 찾지 못했다는 답을 유도한다

**연관**: [[KB-PRD-001#R3]] [[KB-PRD-001#R5]]
