# PRD — 제품 요구

## 1. 목표

#### G1 노트의 무료 웹 발행
Obsidian 노트를 비용 없이 웹사이트로 발행한다.

#### G2 노트 근거 한국어 챗봇
사이트 방문자가 질문하면 노트에 근거해서만 한국어로 답하는 챗봇을 제공한다.

#### G3 관찰 가능한 검색·생성
챗봇이 무엇을 검색했고 LLM에 무엇을 넣었는지 추적할 수 있게 한다.

## 2. 비목표

| 비목표 | 이유 |
|---|---|
| Elasticsearch/OpenSearch 도입 | 상시 서버 비용 발생. 현재 규모에서는 프로세스 내 BM25로 충분 ([[KB-RFQ-001#Q4]]). 규모가 커지면 재검토 |
| 실시간 색인 | 노트 갱신 빈도가 낮아 수동 배치 재색인으로 충분 |
| 방문자 계정·인증 | 공개 지식베이스라 불필요 |
| 서버 측 대화 이력 저장 | 멀티턴은 제공하되([[#R7]]) 이력은 클라이언트가 보내는 것만 쓴다. 서버에 이력 DB를 두면 무료 플랜 제약·개인정보 관리 부담이 생김 |

## 3. 요구사항

### 3.1 기능

#### R1 정적 사이트 발행

근거: [[KB-RFQ-001#Q1]]

Obsidian 볼트의 마크다운을 Quartz로 빌드해 GitHub Pages에 발행한다. 위키링크·백링크·그래프 등 Obsidian의 탐색 경험을 유지한다.

- [ ] 노트를 push하면 자동으로 사이트에 반영된다
- [ ] 위키링크·그래프 뷰가 웹에서 동작한다

#### R2 챗봇 위젯

근거: [[KB-RFQ-001#Q2]]

사이트의 모든 페이지에서 질문을 입력할 수 있는 챗봇 위젯을 제공한다. 답변과 함께 참조한 노트 출처를 보여주고, 백엔드 콜드 스타트 시 지연 안내 문구를 표시한다.

- [ ] 질문 전송 후 답변과 출처 목록이 표시된다
- [ ] 콜드 스타트 지연 안내가 표시된다

#### R3 노트 근거 답변 생성

근거: [[KB-RFQ-001#Q2]]

검색된 노트 청크에만 근거해 한국어로 답변한다. 근거가 없으면 추측하지 않고 "지식베이스에서 관련 내용을 찾지 못했습니다"라고 답한다.

- [ ] 노트에 없는 질문에 추측 답변을 하지 않는다
- [ ] 응답에 참조 노트 경로 목록이 포함된다

#### R4 하이브리드 검색

근거: [[KB-RFQ-001#Q4]]

벡터 검색(의미)과 BM25 키워드 검색을 병행하고 결과를 순위 융합(RRF)한다. BM25는 한국어 형태소 단위로 토큰화해 조사가 붙어도 같은 단어로 매칭한다.

- [ ] 고유명사·정확한 용어 질의에서 해당 노트가 상위 결과에 든다
- [ ] "임베딩을"과 "임베딩"이 같은 토큰으로 매칭된다
- [ ] 노트 재색인 시 BM25 색인이 별도 작업 없이 따라온다

#### R5 LangSmith 추적

근거: [[KB-RFQ-001#Q5]]

질문 1건의 검색~답변 생성 전 과정을 LangSmith에 하나의 trace로 기록한다. 환경변수로 켜고 끄며, 미설정 시에도 챗봇은 정상 동작한다.

- [ ] /chat 1회 호출이 rag_chat trace 1건으로 기록된다
- [ ] trace에서 검색된 청크와 LLM 입력을 확인할 수 있다
- [ ] LangSmith 키가 없어도 챗봇이 동작한다

#### R6 노트 갱신 반영 절차

근거: [[KB-RFQ-001#Q6]]

Python이 없는 작업 PC에서 Docker로 재색인을 실행하고, 커밋·push만으로 라이브에 반영되는 절차를 제공한다.

- [ ] 재색인부터 라이브 반영까지 로컬 Python 설치 없이 가능하다

#### R7 멀티턴 대화

근거: [[KB-RFQ-001#Q7]]

방문자가 앞선 질문·답변을 이어받아 추가 질문을 할 수 있다. 후속 질문("그건 왜 그래?", "더 자세히")은 직전 대화 맥락 안에서 해석하며, 맥락을 반영해 노트를 다시 검색한다. 답변의 근거 원칙은 [[#R3]]을 그대로 따른다.

- [ ] 직전 답변을 가리키는 후속 질문("그건 왜?")이 대화 맥락으로 해석돼 답변된다
- [ ] 후속 질문에서도 출처 목록이 함께 표시된다
- [ ] 방문자가 새 대화를 시작할 수 있다

### 3.2 비기능

#### N1 고정비 0원

근거: [[KB-RFQ-001#Q3]]

- [ ] 호스팅·서버·검색엔진·관찰 도구 모두 무료 플랜 범위 안이다
- [ ] 종량 과금은 OpenAI API 호출뿐이다

#### N2 무료 플랜 자원 제약 내 동작

- [ ] 백엔드가 Render 무료 플랜(RAM 512MB)에서 기동·응답한다

#### N3 키·접근 보호

- [ ] OpenAI·LangSmith API 키는 서버 환경변수로만 존재하고 프론트엔드·저장소에 노출되지 않는다
- [ ] 챗 API는 허용된 도메인(GitHub Pages·로컬 개발)에서만 호출된다 (CORS)

## 4. 성공지표

| 지표 | 목표 |
|---|---|
| 키워드 질의 검색 적중 | 노트에 있는 고유명사 질의 시 해당 노트가 출처 상위 4개 안에 포함 |
| 운영 고정비 | 월 0원 유지 |
| 추적 기록 | 추적 활성 상태에서 /chat 호출의 100%가 trace로 남음 |
| 후속 질문 응답 | 대화 맥락이 필요한 후속 질문이 맥락 없이 답한 것과 다른, 맥락에 맞는 답을 받음 |

## 5. 미결사항

- [ ] Render 배포 실패: [[#R4]]·[[#R5]]가 라이브에 미반영. [[#N2]](512MB)와 kiwipiepy 메모리 사용량 충돌 의심 — 원인 확인 후 필요 시 경량 토크나이저로 대체
- [ ] RRF 가중치(BM25 0.4 / 벡터 0.6) 실사용 기반 튜닝
- [ ] 노트 규모 증가 시 Elasticsearch 전환 재검토 기준
- [ ] 멀티턴 이력 유지 범위: 브라우저 세션 내만인지, 새로고침 후에도 유지할지 ([[KB-RFQ-001#Q7]] 미정 항목)
- [ ] 멀티턴 이력이 길어질 때 LLM 입력 토큰(비용) 상한을 어떻게 둘지
