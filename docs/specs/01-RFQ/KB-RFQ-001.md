# RFQ — 요구·인터뷰

## 1. 배경과 동기

개인이 Obsidian으로 쌓아 온 마크다운 노트(지식베이스)를 웹사이트로 공개하고, 방문자가 노트 내용에 대해 자연어로 질문하면 노트에 근거해 답하는 챗봇을 붙이고 싶다. 운영 비용은 들이고 싶지 않다.

## 2. 명세 체인

이 문서는 이미 구축·배포된 시스템을 소급 문서화하며 시작한다. 이후 변경(검색 개선, 관찰 도구 도입)부터는 이 체인을 근거로 진행한다.

## 3. 요구 사항

#### Q1 Obsidian 노트를 웹사이트로 공개

Obsidian 볼트의 마크다운 노트를 그대로 웹사이트로 발행하고 싶다. 위키링크·그래프 등 Obsidian의 모양을 유지하면 좋겠다.

#### Q2 노트에 근거해 답하는 챗봇

공개된 사이트에서 방문자가 질문을 입력하면, 노트 내용을 검색해 그 근거로만 한국어 답변을 주는 챗봇을 원한다. 노트에 없는 내용은 모른다고 답해야 한다.

#### Q3 무료 운영

호스팅·서버 비용 없이(무료 플랜 범위 안에서) 운영하고 싶다.

#### Q4 검색 품질 개선 — 키워드 검색 보강

벡터 검색만으로는 부족해 Elasticsearch 전환을 검토했으나, 비용이 들지 않는 방식을 우선하기로 했다. BM25 키워드 검색을 기존 벡터 검색과 병행(하이브리드)해 달라.

#### Q5 검색·답변 과정 관찰(LangSmith)

챗봇이 어떤 청크를 찾았고 LLM에 무엇이 들어갔는지 추적·관찰하고 싶다. LangSmith를 적용해 달라.

#### Q6 노트 갱신 반영 절차

노트를 수정·추가하면 챗봇 검색 대상에도 반영할 수 있는 절차가 필요하다. 단, 작업 PC에 Python이 설치되어 있지 않다.

#### Q7 멀티턴 대화

한 번 묻고 끝나는 게 아니라, 앞선 질문·답변을 이어받아 추가 질문("그건 왜 그래?", "더 자세히")을 할 수 있는 대화형 챗봇을 원한다.

## 4. 사용자와 환경

- **사용자**: 운영자 본인 1명(노트 작성·배포)과 사이트 방문자(질문·열람).
- **작업 PC**: Windows 11, Python 미설치, Docker 사용 가능.
- **계정**: GitHub(공개 `knowledgeBase` / 비공개 `knowledgeBase-backend`), Render 무료 플랜, OpenAI API, LangSmith 무료 플랜.
- **언어**: 노트와 질문·답변 모두 한국어 중심.

## 5. 첫 프로젝트

지식베이스 사이트와 챗봇은 이미 배포되어 있다(GitHub Pages + Render). 이번 범위는 [[#Q4]]·[[#Q5]]의 적용과 그 문서화, 그리고 [[#Q7]]의 명세다.

## 6. 미정

- [ ] Render 무료 플랜에서 새 버전(하이브리드 검색) 배포 실패 원인 확인·해결 (메모리 부족 의심)
- [ ] 향후 Elasticsearch(또는 OpenSearch) 전환 여부 — 노트 규모가 커지거나 비용을 쓸 수 있게 되면 재검토
- [ ] 멀티턴 대화 이력을 어디까지 유지할지(브라우저 세션 내만인지, 새로고침 후에도인지)
